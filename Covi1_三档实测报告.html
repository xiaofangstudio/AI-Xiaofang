五、这次踩到并处理掉的问题

1. 抢显卡会让小方启动卡死（已定位根因，给出规避办法）

当 学习小说.py 占满显卡时，小方启动会停住不走。用看门狗抓到的线程栈是唯一的、明确的：

File "xiaofang_covi1.py", line 3806 in _quantize      <- float(_m) 等显卡同步
File "xiaofang_covi1.py", line 3794 in __init__       <- Qint
File "xiaofang_covi1.py", line 3775 in _WQ
File "xiaofang_covi1.py", line 4052 in __init__       <- TransformerBlock
File "xiaofang_covi1.py", line 4096 in __init__       <- DeepThinkTransformer
File "xiaofang_covi1.py", line 7645 in __init__       <- XiaoFang

即：权重量化那一步要把显存上的标量搬回主机，显卡被别的进程占满时这一步会无限期排队。规避办法：录制或演示小方之前，先让 学习小说.py 收工（或关掉）再启动；本次三档实测即改走 CPU 后端避开争用，引擎构建 42 秒，对话全程正常。

2. 「后台训练没派出去」是误判（已澄清）

早先的测试脚本在后台训练还没收工时就去读状态，于是看到「累计 0 次 / 栅栏关闭」，一度像缺陷。加上「等它收工再读」之后，三档实测全部显示 后台训练 1 次、栅栏终态已放行，证实 v2.3 的后台训练单槽工作正常：训练不再占用用户等待时间，也不会把下一句挡死。
